publish updates, how to connect a custom domain, and how to add an in-page
Trixa popup after Trixa enables embedding. It is written for the website owner
and the person maintaining the React code. Open this UTF-8 text file in
Notepad, Visual Studio Code, or Word. Code examples use plain quotation marks.

  The first place to look for routine settings. Holds CONTACT.phone,

  and the derived whatsappNumber. Change your contact details here once.

src/main.jsx

3  ADD OR CHANGE THE PHONE AND WHATSAPP NUMBERS
==========================================================================

1. Sign in to GitHub and open the private Fanaar repository.
2. Open src, then config.js. Use the pencil or Edit this file action.
3. Find this block:

   export const CONTACT = {
     phone: '',
     whatsapp: '',
   };

4. Put your real business number between the single quotes. This is an
   EXAMPLE ONLY, not Fanaar's actual number:

   export const CONTACT = {
     phone: '+255700000000',
     whatsapp: '255700000000',
   };

   For a Tanzanian number, use country code 255 and omit the local leading
   zero. Phone can include the +. WhatsApp should contain international
   digits only, with no +, spaces or punctuation. Use your complete real
   number. The two numbers can be the same or different.

5. Leave whatsapp as '' if you only want calls. Leave phone as '' if calls
   are unavailable. Do not leave a sample number in a published site.
6. Commit with a clear message such as "Update business contact number".
7. Wait for the Build check to pass, then publish using section 6.
8. Check on a phone: the number should be visible in the top bar immediately.
   Tap the phone link and confirm the device offers a call to the right
   number. The visitor's device controls whether a call is placed. Desktop
   computers may require a calling application.
9. Open Contact us and check the call link and WhatsApp destination too.

If only WhatsApp is configured, the top bar uses that number as a WhatsApp
link. If you want the top number to make a phone call, configure phone.
Until a number is configured, the site displays "Number coming soon".

4  CHANGE ROUTES WORDING PHOTOS COLOURS AND THE ADMIN LINK
==========================================================================

Routes
  Edit ROUTES in src/config.js to change the route cards. Each entry has
  from, to, code and direction. Current service is Dar es Salaam to Zanzibar,
  Zanzibar to Dar es Salaam, and Zanzibar to Tanga.

  Route cards are generated from ROUTES. Other route references are written
  separately in src/main.jsx: the top bar, hero, CoastMap, FAQ and footer.
  Update these as well if the route network changes. CoastMap is an SVG
  illustration; changing ROUTES does not redraw it automatically. Also
  update the description in index.html when necessary.

Wording and company logo
  Search for the visible wording in src/main.jsx and edit the relevant JSX
  text. Preserve tags, braces and quotation marks. FAQ content is in faqs.
  Brand controls the page logo and company lettering. The current page is
  English; translating it requires reviewing all visible text and labels.

Photos
  For the simplest replacement, use the same filenames in public/images.
  Keep the files reasonably small. If the subject changes, update alt text
  in src/main.jsx. To use a different filename, update the matching image
  path in src/main.jsx too. Update public/images/credits.txt and README.md
  for the new source and keep any required licence information.

Colours and spacing
  Start with :root in src/styles.css. --orange controls many action buttons;
  --ink controls the main dark colour; --cream controls the light background.
  Search for individual fixed hex values if a component does not follow a
  variable. Test contrast, focus outlines and small screens after changes.

Browser tab and search description
  Change <title> and the description meta tag in index.html. Search engines
  choose when to refresh their listing; a deployment does not force an
  immediate search result change.

Trixa account links
  Change TRACKING_URL or QUOTE_URL in src/config.js only when Trixa supplies
  the correct replacement. Test with the intended branch/account. Do not
  guess a tracking API or quote submission endpoint.

Admin login
  Change ADMIN_LOGIN_URL in src/config.js. The discreet footer link opens
  that address in a new tab. Its wording and placement are in the footer
  inside src/main.jsx. It is a shortcut, not an access-control mechanism;
  Trixa still authenticates staff. Keep staff credentials out of this repo.

==========================================================================
8  PREPARE FOR TRIXA EMBEDDING
==========================================================================

What embedding means
  A real Trixa page appears in an iframe inside a dialog over Fanaar. The
  customer can still see Fanaar behind it. They fill and submit Trixa's form
  inside that frame, or view tracking results there. This needs no separate
  Fanaar server. It is different from recreating Trixa's form in React.

Provider prerequisites
1. Give Trixa the exact website origin to allow. An origin is scheme and
   hostname, plus a port when used. For a GitHub project URL, use
   https://abuubakry-ali.github.io, without /fanaar-logistics/.
   For your own domain, supply https://example.com and https://www.example.com
   only if both are actually used. Do not send the example domain as yours.
2. Ask them to allow both the tracking and enquiry pages listed in section 1,
   including redirects and the pages reached after submission.
3. They must adjust their HTTP response headers. A policy example, using an
   example domain only, is:

   Content-Security-Policy: frame-ancestors 'self' https://example.com;

   Trixa should merge the allowed origins into its existing policy and remove
   conflicting X-Frame-Options restrictions for these pages. A Fanaar HTML
   meta tag cannot change the provider's framing policy. ALLOW-FROM is not a
   current replacement for a proper frame-ancestors policy.
4. Ask Trixa to test cross-site sessions, CSRF protection and successful
   enquiry submission inside the iframe. Allowing display alone does not
   guarantee form submission. Cookie rules, including browser restrictions
   on third-party cookies, can still block sessions. SameSite=None; Secure
   may be part of their solution but is not sufficient in every browser.
   Do not disable CSRF protection to make an iframe work.
5. Obtain their recommended iframe configuration and confirm the account
   receiving quotes. Keep a separate-page fallback available.

You do not need CORS permission merely to display a Trixa iframe. Browser
fetch/API integration is a different approach and requires a provider-
supported API and appropriate access. This guide uses the existing pages.

If Fanaar's host later adds its own Content-Security-Policy, its frame-src
must also allow https://cargo.trixa.net. Test the published Fanaar page
directly. A preview inside someone else's iframe adds extra ancestors that
Trixa may not permit.

The future changes in section 9 are not active in the current website.

9.2  CREATE src/PortalDialog.jsx WITH THIS COMPLETE CONTENT

```jsx
import React, { createContext, useCallback, useContext, useEffect, useId, useRef, useState } from 'react';
import { ExternalLink, X } from 'lucide-react';
import { EMBED_TRIXA } from './config';

const PortalContext = createContext(null);

export function usePortal() {
  const openPortal = useContext(PortalContext);
  if (!openPortal) throw new Error('usePortal must be inside PortalProvider.');
  return openPortal;
}

function PortalDialog({ portal, onClose }) {
  const dialogRef = useRef(null);
  const headingId = useId();
  const helpId = useId();

  useEffect(() => {
    const dialog = dialogRef.current;
    const previousFocus = document.activeElement;
    const previousOverflow = document.body.style.overflow;
    document.body.style.overflow = 'hidden';
    if (!dialog.open) dialog.showModal();

    return () => {
      if (dialog.open) dialog.close();
      document.body.style.overflow = previousOverflow;
      if (previousFocus instanceof HTMLElement && previousFocus.isConnected) {
        previousFocus.focus({ preventScroll: true });
      }
    };
  }, [onClose]);

  return (
    <dialog
      ref={dialogRef}
      className="portal-dialog"
      aria-labelledby={headingId}
      aria-describedby={helpId}
      onCancel={onClose}
    >
      <header className="portal-dialog-header">
        <div>
          <h2 id={headingId}>{portal.title}</h2>
          <p id={helpId}>Complete the Trixa page below. Use Close when you are finished.</p>
        </div>
        <button type="button" className="portal-close" onClick={onClose} autoFocus>
          <X size={18} aria-hidden="true" /> Close
        </button>
      </header>
      <iframe
        key={portal.url}
        className="portal-frame"
        src={portal.url}
        title={`${portal.title} — Trixa`}
      />
      <footer className="portal-dialog-footer">
        <span>If the page does not display or submit, open it separately.</span>
        <a href={portal.url} target="_blank" rel="noopener noreferrer">
          Open separately <ExternalLink size={15} aria-hidden="true" />
        </a>
      </footer>
    </dialog>
  );
}

export function PortalProvider({ children }) {
  const [portal, setPortal] = useState(null);
  const closePortal = useCallback(() => setPortal(null), []);

  const openPortal = useCallback((url, title) => {
    if (!EMBED_TRIXA || typeof window.HTMLDialogElement?.prototype?.showModal !== 'function') {
      return false;
    }
    setPortal({ url, title });
    return true;
  }, []);

  return (
    <PortalContext.Provider value={openPortal}>
      {children}
      {portal && <PortalDialog portal={portal} onClose={closePortal} />}
    </PortalContext.Provider>
  );
}
```

This deliberately keeps portal state separate from ContactDialog's modal state. A quote opened from the contact dialog closes the contact dialog and opens the portal without its contact-close callback cancelling the portal. The iframe loads only URLs supplied by the code below. No success-message listener is fabricated. The iframe has no sandbox or credentialless attribute: adding restrictions without Trixa's guidance can break its JavaScript, form submission, cookies, or downloads.

9.4  UPDATE src/main.jsx — REPLACE THE ENTIRE QuoteLink FUNCTION

Replace from function QuoteLink(...) through its closing brace immediately before function ContactDialog(...) with:

```jsx
function QuoteLink({ children, className = '', onNavigate, ...props }) {
  const openEmbeddedPortal = usePortal();

  function openQuote(event) {
    if (event.button !== 0 || event.ctrlKey || event.metaKey || event.shiftKey || event.altKey) return;
    if (openEmbeddedPortal(QUOTE_URL, 'Get a quote') || openPortalPopup(QUOTE_URL)) {
      event.preventDefault();
    }
    onNavigate?.();
  }

  return (
    <a
      href={QUOTE_URL}
      target="_blank"
      rel="noopener noreferrer"
      className={className}
      title={EMBED_TRIXA ? 'Opens the Trixa quote form on this page' : 'Opens the Trixa quote form in a separate window'}
      onClick={openQuote}
      {...props}
    >
      {children}
    </a>
  );
}
```

All existing quote links now share the same behavior. Normal clicks use the iframe when enabled; Ctrl/Cmd-click and other modified clicks keep the normal external-link behavior. With the flag false, the existing popup/new-tab fallback remains.

9.5  UPDATE src/main.jsx — TRACKING

Add this as the first line inside function App() before its existing state declarations:

```jsx
const openEmbeddedPortal = usePortal();
```

Replace the entire existing handleTracking function with:

```jsx
function handleTracking(event) {
  const reference = tracking.trim();
  if (!reference) {
    event.preventDefault();
    event.currentTarget.elements.ref.setCustomValidity('Enter a tracking reference or phone number.');
    event.currentTarget.elements.ref.reportValidity();
    return;
  }

  const destination = new URL(TRACKING_URL);
  destination.searchParams.set('ref', reference);
  if (openEmbeddedPortal(destination.href, 'Track your package') || openPortalPopup(destination.href)) {
    event.preventDefault();
  }
}
```

Keep the tracking form's action, method="get", target="_blank", rel, input name="ref", and onChange logic as they are. They preserve the native form fallback. URLSearchParams encodes phone numbers, spaces, + signs, and references correctly. Do not add quote-form query prefilling: the inspected enquiry page ignores name, phone, cargo, route, and message query parameters.

9.9  TEST, ENABLE, AND PUBLISH

Install dependencies if needed with npm ci. Run npm run build. With EMBED_TRIXA = false, npm run dev should preserve the current popup/new-tab behavior. After Trixa approval, change only the flag to true and test from an origin Trixa explicitly allowed. Local preview uses npm run preview after building; if Trixa allows only production, deploy to that allowed origin for the integration check.

Verify: every quote button including the one inside Contact us; quote form field validation; a known tracking reference and phone number; an unknown reference; Close button; Escape when focus is on Fanaar controls; keyboard focus after close; body scroll restoration; narrow mobile layouts; and the Open separately fallback. Escape pressed while focus is inside the cross-origin frame may be handled there, so the visible Close button must remain available. Confirm that Admin login still opens externally. Coordinate one clearly marked test enquiry with Trixa and confirm it arrives in the intended account. A form merely displaying is not proof that its CSRF/session submission works. Do not submit customer data for a connectivity test.

Commit and push source changes to main. Wait for the Build workflow to pass. Once GitHub Pages is enabled for the account/repository and Settings > Pages > Source is GitHub Actions, open Actions > Deploy to GitHub Pages > Run workflow, select main, and run it. Publishing is manual in this export: pushing main runs Build but does not deploy. Wait for the deployment to succeed, then open the published URL and check it. Update README's Trixa section to explain the feature flag, the manual Close control, and the external fallback rather than saying embedding is always blocked. Store this guide outside public assets; no server credentials or tokens belong in it.

If embedding fails later, set EMBED_TRIXA back to false, commit, and push to main. Wait for Build to pass, then run Actions > Deploy to GitHub Pages > Run workflow on main and wait for it to finish. The published site restores popup/new-tab behavior only after that manual deployment succeeds. The same quote links and tracking form provide the fallback without removing the new module. Keep src/portal.js for that fallback.

LIMITS THAT MUST REMAIN CLEAR

The parent cannot inspect Trixa's success screen, fields, branding, or document height because they are cross-origin. Leave the dialog open after a quote is sent until the customer closes it. Do not use iframe onLoad as proof of a successful load or submission: load may fire even when an iframe fails. Do not add a timer to declare a quote submitted. Keep fixed viewport-based iframe sizing and scrolling. Automatic close or dynamic content resizing needs a documented cooperation mechanism from Trixa, such as validated postMessage events. No such event contract was present in the inspected source, so this implementation does not listen for one. If Trixa later supplies it, validate both exact event.origin and event.source === iframeRef.current.contentWindow, plus message type/shape, before acting.

10  TROUBLESHOOTING AND RECOVERY
==========================================================================

The updated number is not live
  Confirm the change is in src/config.js on main, the Build check passed,
  and the correct host was deployed. A successful Build alone does not
  publish. Refresh the actual live URL. The older preview is a separate
  deployment and does not follow GitHub automatically.

The top number opens WhatsApp instead of calling
  Configure CONTACT.phone. A WhatsApp-only configuration intentionally uses
  the WhatsApp link in the top bar. Check the full international number.

GitHub Pages says upgrade or make the repository public
  This is the account plan restriction. Keep the repository private. The
  owner must obtain an eligible plan, or choose another static host later.
  Changing the domain does not bypass the restriction.

Blank page or missing photos after publishing
  Check that dist was built for the correct base path. The project subfolder
  needs /fanaar-logistics/; a domain root needs /. The Pages workflow chooses
  this automatically after Pages is configured. Check case-sensitive image
  filenames and paths. Never upload raw src files as the built website.

Trixa opens a tab instead of a small browser window
  This is expected on mobile or when browser policy blocks a popup. The
  current fallback still opens the real Trixa page. Browser controls and
  address bars cannot be hidden reliably by this website.

An embedded popup says refused to connect or is blank
  Open its separate-page fallback. Ask Trixa to check X-Frame-Options and
  Content-Security-Policy on the exact response, redirects and result pages.
  Confirm the allowed origin matches the live domain. Fanaar cannot reliably
  detect these frame failures using iframe onLoad or onError.

The embedded form displays but does not submit
  Trixa must inspect sessions, cookies and CSRF errors inside the iframe.
  Test in the affected mobile browser and with third-party cookies blocked.
  Continue using the separate-page fallback until submission is verified.

The embedded dialog does not close after sending
  Manual closing is the default. Fanaar cannot read a cross-origin success
  screen. Automatic closing or content-based resizing needs a Trixa-supported
  postMessage contract. If one is added, validate the sender origin, source
  iframe window and agreed message schema. Do not guess an event name or
  treat any received message as proof of a successful quote.

Recover a source change
1. Open the affected file's History in GitHub and identify the last working
   version. Copy that version's contents back into the current file, or have
   the maintainer revert the relevant commit through their Git workflow.
2. Commit the repair to main and wait for Build to pass.
3. Run the host's deployment again and verify the actual live website.
4. For the future embedding implementation, switch EMBED_TRIXA back to false
   and deploy if Trixa stops supporting frames. That restores external links.
