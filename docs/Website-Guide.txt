src/config.js
  The first place to look for routine settings. Holds CONTACT.phone,

==========================================================================
8  PREPARE FOR PORTAL EMBEDDING
==========================================================================

What embedding means
  A real service page appears in an iframe inside a dialog over Fanaar. The
  customer can still see Fanaar behind it. They fill and submit the provider's form
  inside that frame, or view tracking results there. This needs no separate
  Fanaar server. It is different from recreating the provider's form in React.

Provider prerequisites
1. Give the provider the actual website origin: https://fanaarlogistics.com.
   An origin is scheme and hostname, plus a port when used; it has no path.
   Include https://www.fanaarlogistics.com only if that is also an active
   website origin. Include local preview origins only if explicitly allowed.
2. Ask them to allow both https://tracking.fanaarlogistics.com/ and
   https://quote.fanaarlogistics.com/ to appear in a frame, including any
   redirects and result pages. A custom hostname does not grant permission.
3. They must configure their HTTP response headers. For the current website,
   an example allowance is:

   Content-Security-Policy: frame-ancestors 'self' https://fanaarlogistics.com;

   The provider should merge approved origins into its existing policy and
   remove conflicting X-Frame-Options restrictions on these public pages.
   A Fanaar HTML meta tag cannot change the provider's framing policy.
   ALLOW-FROM is not a current replacement for frame-ancestors.
4. Ask the provider to test cookies, sessions, CSRF protection and successful
   enquiry submission inside the frame. The branded subdomains are still
   different origins from the main website. They may be same-site when they
   stay under the same HTTPS parent domain, but cross-site redirects and
   browser cookie restrictions can still affect the flow. The provider must
   choose a supported design and retain CSRF protection. Display alone is
   not proof of successful submission. Do not disable security to make it work.
5. Obtain the recommended iframe configuration and confirm the account that
   receives quotes. Keep a separate-page fallback available.

CORS permission is not needed merely to display a provider page in an iframe.
Browser fetch/API integration is a different approach and requires a supported
API and appropriate access. This guide's future example embeds the pages.

If Fanaar's host adds its own Content-Security-Policy, its frame-src must allow
https://tracking.fanaarlogistics.com and https://quote.fanaarlogistics.com.
Test the published Fanaar page directly. Preview tools may add extra frame
ancestors that the provider has not approved.

The future changes in section 9 are not active in the current website.

9.2  CREATE src/PortalDialog.jsx WITH THIS COMPLETE CONTENT

```jsx
import React, { createContext, useCallback, useContext, useEffect, useId, useRef, useState } from 'react';
import { ExternalLink, X } from 'lucide-react';
import { EMBED_PORTALS } from './config';

const PortalContext = createContext(null);

export function usePortal() {
  const openPortal = useContext(PortalContext);
  if (!openPortal) throw new Error('usePortal must be inside PortalProvider.');
  return openPortal;
}

function PortalDialog({ portal, onClose }) {
  const dialogRef = useRef(null);
  const headingId = useId();
  const helpId = useId();

  useEffect(() => {
    const dialog = dialogRef.current;
    const previousFocus = document.activeElement;
    const previousOverflow = document.body.style.overflow;
    document.body.style.overflow = 'hidden';
    if (!dialog.open) dialog.showModal();

    return () => {
      if (dialog.open) dialog.close();
      document.body.style.overflow = previousOverflow;
      if (previousFocus instanceof HTMLElement && previousFocus.isConnected) {
        previousFocus.focus({ preventScroll: true });
      }
    };
  }, [onClose]);

  return (
    <dialog
      ref={dialogRef}
      className="portal-dialog"
      aria-labelledby={headingId}
      aria-describedby={helpId}
      onCancel={onClose}
    >
      <header className="portal-dialog-header">
        <div>
          <h2 id={headingId}>{portal.title}</h2>
          <p id={helpId}>Complete the service page below. Use Close when you are finished.</p>
        </div>
        <button type="button" className="portal-close" onClick={onClose} autoFocus>
          <X size={18} aria-hidden="true" /> Close
        </button>
      </header>
      <iframe
        key={portal.url}
        className="portal-frame"
        src={portal.url}
        title={`${portal.title} — Fanaar Logistics`}
      />
      <footer className="portal-dialog-footer">
        <span>If the page does not display or submit, open it separately.</span>
        <a href={portal.url} target="_blank" rel="noopener noreferrer">
          Open separately <ExternalLink size={15} aria-hidden="true" />
        </a>
      </footer>
    </dialog>
  );
}

export function PortalProvider({ children }) {
  const [portal, setPortal] = useState(null);
  const closePortal = useCallback(() => setPortal(null), []);

  const openPortal = useCallback((url, title) => {
    if (!EMBED_PORTALS || typeof window.HTMLDialogElement?.prototype?.showModal !== 'function') {
      return false;
    }
    setPortal({ url, title });
    return true;
  }, []);

  return (
    <PortalContext.Provider value={openPortal}>
      {children}
      {portal && <PortalDialog portal={portal} onClose={closePortal} />}
    </PortalContext.Provider>
  );
}
```

This deliberately keeps portal state separate from ContactDialog's modal state. A quote opened from the contact dialog closes the contact dialog and opens the portal without its contact-close callback cancelling the portal. The iframe loads only URLs supplied by the code below. No success-message listener is fabricated. The iframe has no sandbox or credentialless attribute: adding restrictions without the provider's guidance can break its JavaScript, form submission, cookies, or downloads.

9.4  UPDATE src/main.jsx — REPLACE THE ENTIRE QuoteLink FUNCTION

Replace from function QuoteLink(...) through its closing brace immediately before function ContactDialog(...) with:

```jsx
function QuoteLink({ children, className = '', onNavigate, ...props }) {
  const openEmbeddedPortal = usePortal();

  function openQuote(event) {
    if (event.button !== 0 || event.ctrlKey || event.metaKey || event.shiftKey || event.altKey) return;
    if (openEmbeddedPortal(QUOTE_URL, 'Get a quote') || openPortalPopup(QUOTE_URL)) {
      event.preventDefault();
    }
    onNavigate?.();
  }

  return (
    <a
      href={QUOTE_URL}
      target="_blank"
      rel="noopener noreferrer"
      className={className}
      title={EMBED_PORTALS ? 'Opens the quote form on this page' : 'Opens the quote form in a separate window'}
      onClick={openQuote}
      {...props}
    >
      {children}
    </a>
  );
}
```

All existing quote links now share the same behavior. Normal clicks use the iframe when enabled; Ctrl/Cmd-click and other modified clicks keep the normal external-link behavior. With the flag false, the existing popup/new-tab fallback remains.

9.5  UPDATE src/main.jsx — TRACKING

```jsx
const openEmbeddedPortal = usePortal();
```

Replace the entire existing handleTracking function with:

```jsx
function handleTracking(event) {
  const reference = tracking.trim();
  if (!reference) {
    event.preventDefault();
    event.currentTarget.elements.ref.setCustomValidity('Enter a tracking reference or phone number.');
    event.currentTarget.elements.ref.reportValidity();
    return;
  }

  const destination = new URL(TRACKING_URL);
  destination.searchParams.set('ref', reference);
  if (openEmbeddedPortal(destination.href, 'Track your package') || openPortalPopup(destination.href)) {
    event.preventDefault();
  }
}
```

Keep the tracking form's action, method="get", target="_blank", rel, input name="ref", and onChange logic as they are. They preserve the native form fallback. URLSearchParams encodes phone numbers, spaces, + signs, and references correctly. Do not add quote-form query prefilling unless the provider documents and verifies it for the new portal. Support for such parameters has not been confirmed.

9.9  TEST, ENABLE, AND PUBLISH

Install dependencies if needed with npm ci. Run npm run build. With EMBED_PORTALS = false, npm run dev should preserve the current popup/new-tab behavior. After provider approval, change only the flag to true and test from an origin the provider explicitly allowed. Local preview uses npm run preview after building; if the provider allows only production, deploy to that allowed origin for the integration check.

Verify: every quote button including the one inside Contact us; quote form field validation; a known tracking reference and phone number; an unknown reference; Close button; Escape when focus is on Fanaar controls; keyboard focus after close; body scroll restoration; narrow mobile layouts; and the Open separately fallback. Escape pressed while focus is inside the cross-origin frame may be handled there, so the visible Close button must remain available. Confirm Admin login is hidden while its setting is empty; test a confirmed external login only if it is enabled later. Coordinate one clearly marked test enquiry with the provider and confirm it arrives in the intended account. A form merely displaying is not proof that its CSRF/session submission works. Do not submit customer data for a connectivity test.

Commit and push source changes to main. Wait for the Build workflow to pass. GitHub Pages is enabled with GitHub Actions as its source. Open Actions > Deploy to GitHub Pages > Run workflow, select main, and run it. Publishing is manual in this export: pushing main runs Build but does not deploy. Wait for the deployment to succeed, then open the published URL and check it. Update this guide's current-status section to describe the activated feature flag, manual Close control, and external fallback. Store this guide outside public assets; no server credentials or tokens belong in it.

If embedding fails later, set EMBED_PORTALS back to false, commit, and push to main. Wait for Build to pass, then run Actions > Deploy to GitHub Pages > Run workflow on main and wait for it to finish. The published site restores popup/new-tab behavior only after that manual deployment succeeds. The same quote links and tracking form provide the fallback without removing the new module. Keep src/portal.js for that fallback.

LIMITS THAT MUST REMAIN CLEAR

The parent cannot inspect the provider's success screen, fields, branding, or document height because they are cross-origin. Leave the dialog open after a quote is sent until the customer closes it. Do not use iframe onLoad as proof of a successful load or submission: load may fire even when an iframe fails. Do not add a timer to declare a quote submitted. Keep fixed viewport-based iframe sizing and scrolling. Automatic close or dynamic content resizing needs a documented cooperation mechanism from the provider, such as validated postMessage events. No provider event contract has been confirmed for the new portals, so this implementation does not listen for one. If the provider later supplies it, validate both exact event.origin and event.source === iframeRef.current.contentWindow, plus message type/shape, before acting.

==========================================================================
10  TROUBLESHOOTING AND RECOVERY
==========================================================================

A configured service hostname shows a parking page or 404
  The provider must connect the tracking and quote instances, confirm DNS,
  exact paths and HTTPS, then verify the correct account and complete flows.
  Replacing a URL in config.js cannot provision the external application.
  Keep this status distinct from whether the Fanaar website itself deployed.

The updated number is not live
  Confirm the change is in src/config.js on main, the Build check passed,
  and the correct host was deployed. A successful Build alone does not
  publish. Refresh the actual live URL. The older preview is a separate
  deployment and does not follow GitHub automatically.

The top number opens WhatsApp instead of calling
  Configure CONTACT.phone. A WhatsApp-only configuration intentionally uses
  the WhatsApp link in the top bar. Check the full international number.

GitHub Pages still says upgrade or make the repository public
  The owner has approved public source. Confirm that you are viewing the
  correct public repository and refresh Settings > Pages after the visibility
  change. GitHub Free supports Pages from public repositories. Select GitHub
  Actions as the publishing source and run the manual deployment.

Blank page or missing photos after publishing
  Check that dist was built for the correct base path. The project subfolder
  needs /fanaar-logistics/; a domain root needs /. The Pages workflow chooses
  this automatically after Pages is configured. Check case-sensitive image
  filenames and paths. Never upload raw src files as the built website.

The service opens a tab instead of a small browser window
  This is expected on mobile or when browser policy blocks a popup. The
  current fallback still opens the service page. Browser controls and
  address bars cannot be hidden reliably by this website.

An embedded popup says refused to connect or is blank
  Open its separate-page fallback. Ask the provider to check X-Frame-Options and
  Content-Security-Policy on the exact response, redirects and result pages.
  Confirm the allowed origin matches the live domain. Fanaar cannot reliably
  detect these frame failures using iframe onLoad or onError.

The embedded form displays but does not submit
  The provider must inspect sessions, cookies and CSRF errors inside the iframe.
  Test in the affected mobile browser and with third-party cookies blocked.
  Continue using the separate-page fallback until submission is verified.

The embedded dialog does not close after sending
  Manual closing is the default. Fanaar cannot read a cross-origin success
  screen. Automatic closing or content-based resizing needs a provider-supported
  postMessage contract. If one is added, validate the sender origin, source
  iframe window and agreed message schema. Do not guess an event name or
  treat any received message as proof of a successful quote.

Recover a source change
1. Open the affected file's History in GitHub and identify the last working
   version. Copy that version's contents back into the current file, or have
   the maintainer revert the relevant commit through their Git workflow.
2. Commit the repair to main and wait for Build to pass.
3. Run the host's deployment again and verify the actual live website.
4. For the future embedding implementation, switch EMBED_PORTALS back to false
   and deploy if the provider stops supporting frames. That restores external links.

  [ ] Verify a known tracking reference and an unknown reference.
  [ ] Test quote validation and a clearly labelled test enquiry agreed with
      the business; verify receipt in the intended provider account.
  [ ] Check keyboard navigation, Escape, dialog close and focus return.
  [ ] Check the separate-page fallback, mobile scrolling and cookie limits.
  [ ] Confirm the Build check and actual deployment both succeeded.
